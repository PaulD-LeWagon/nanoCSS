## Post-Sprint Corrections — 2026-05-10

Visual QA after the initial delivery revealed six markup bugs in `show.html.erb`. Root cause: component classes were assumed rather than verified against the SCSS source and the live component catalogue. The showcase was rebuilt after a full audit of every component SCSS file and the catalogue view.

### Bugs Found and Fixed

| Component | Bug | Correct contract |
|---|---|---|
| Carousel | Used `nanocss-carousel-track`, `nanocss-carousel-slide` (invented) | `.carousel-track`, `.carousel-slide` — unprefixed, nested inside `.{prefix}-carousel` |
| Badges | Used `.nanocss-badge-success` BEM pattern (invented) | `.nanocss-badge.success` — modifier class on base element |
| Modal | Used `<div>` + Stimulus controller | `<dialog class="{prefix}-modal">` + native `showModal()`/`close()` |
| Tabs | Used Stimulus + invented nav/button classes | Pure CSS: `<input type="radio">` + `<label>` + `<div class="panel">` |
| Progress | Used `<div class="nanocss-progress-bar">` (invented) | Native `<progress value="" max="">` styled by `_base.scss` |
| Alert Banners | Used `.nanocss-banner-success` etc. (invented) | No alert component exists — section uses `<hgroup>` (Text Banner) |

### Additional Fixes
- `.nanocss-glass` background formula inverted — `calc(1 - surface-opacity)` produced transparent glass for standard presets and opaque glass for Obsidian. Fixed to `color-mix(in srgb, neutral-50 85%, transparent)`.
- 375px horizontal scroll — grid cells lacked `min-width: 0`. Accordion min-content width expanded the sidebar past its grid track.
- Dark mode body — showcase layout was hardcoding `body { background: #f3f4f6 }`, preventing dark mode tokens from applying. Removed; `_base.scss` now controls body background.
- Showcase chrome bleed — initial implementation used the application layout, inheriting the Obsidian dark chrome body styles. Fixed by `layout "showcase"` pointing to a dedicated layout that omits `application.css`.

### Process Note
The correct workflow for any page that uses nanoCSS components:
1. Read the component's `_*.scss` file to establish the exact class contract.
2. Cross-reference with the live component catalogue (`/components`) for the authoritative markup pattern.
3. Never assume class names from the component name alone.

## Sprint Retrospective

### What Shipped
- All 4 stories delivered (11 pts). The `/showcase` page is live at `localhost:3001/showcase` displaying all 19 nanoCSS components in a two-column layout with theme switching, dark mode, and four preset options.

### What Slowed Down
- **Markup-without-reading:** The initial showcase view was written without consulting the SCSS or catalogue, producing six invented class names. This required a complete view rewrite after visual QA. Cost: approximately half the sprint in rework.
- **CSS cascade assumptions:** The dark mode body issue and glass utility formula were both incorrect assumptions about how the nanoCSS token system works.

### What Went Well
- The TDD cycle (red → green → refactor) caught the contract errors immediately once the specs were updated to reflect the actual SCSS API.
- The dedicated `layouts/showcase.html.erb` cleanly solves the chrome bleed problem without any hacks.
- The `min-width: 0` grid fix is textbook and was identified quickly via the JS `getBoundingClientRect` diagnostic.

### Carry-Forward Notes
- **Alert banner component** does not exist yet. The showcase `#alerts` section demonstrates the Text Banner (`hgroup`) as the closest available primitive. A full semantic alert/notification banner component should be planned for a future sprint.
- **Theme Switcher partial** — the user has noted the switcher should be extracted from inline layout HTML into a proper partial. Planned for design augmentation before the next sprint.
- **Obsidian preset** should be added to the main `application.html.erb` theme switcher for parity with the showcase layout.
